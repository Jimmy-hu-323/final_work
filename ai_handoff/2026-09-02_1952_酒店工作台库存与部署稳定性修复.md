# 酒店工作台库存与部署稳定性修复

## 用户目标与范围

- 修复演示准备检查中发现的酒店网页问题，并部署到现有服务器。
- 保留现有酒店数据库、账单、授权、用户数据和其他服务，不重置凭据或创建新密钥。

## 修复内容

- 酒店工作台不再请求已经从当前澳门酒店目录移除的旧酒店 ID。
- 工作台从当前搜索状态选择有效运营酒店，展示与库存数据一致的酒店名称。
- 库存加载记录已请求的酒店，空结果或失败时不再因渲染循环连续重复请求。
- 库存 API 未指定酒店时按评分选择当前目录中的酒店，不再依赖旧种子数据。
- 静态首页由 `hydrateRoot` 改为 `createRoot`；构建产物本来只有加载占位符，没有可供水合的服务端 HotelApp HTML，因此不再产生 React 水合错误。
- 构建脚本自动创建 `dist/server/.wrangler`，避免重新构建后 systemd 的 `ReadWritePaths` 目标缺失并导致服务以 `226/NAMESPACE` 反复重启。
- 后端权威源码和 `project_front` 前端镜像已同步；测试增加旧酒店引用、客户端挂载方式和运行目录断言。
