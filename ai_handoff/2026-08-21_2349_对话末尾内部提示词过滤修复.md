# 对话末尾内部提示词过滤修复

## 用户目标与范围

- 修复“对话”栏目每次回复末尾出现类似提示词、JSON 数据或内部指令的问题。
- 保留 QwenPaw 行程解析、保存确认和本地旅程同步能力。
- 自动清理已有聊天历史中已经显示的内部控制内容。
- 仅修改对话消息及行程桥接相关代码，不改动其他栏目。

## 原因

QwenPaw 在生成或修改行程时，会按 LensGo 手机端桥接协议在回复末尾附带机器可读的 `lensgo-trip-update` JSON。模型有时还会附带 HTML 注释形式的内部提醒，例如提示输出代码块并等待用户确认。

原实现会使用 `extractAgentTripProposal` 解析这些原始内容并弹出保存行程确认框，但流式展示和本地聊天入库仍直接使用同一份原始文本，因此 JSON、内部注释和控制指令也被用户看到。

## 修改文件与关键改动

后端交付树与前端镜像树同步修改：

- `project_backend/middle_stage/Qwen_competion/qwen_compitition/console/src/mobile-local/tripSync.ts`
- `project_backend/middle_stage/Qwen_competion/qwen_compitition/console/src/mobile-local/MobileLocalApp.tsx`
- `project_backend/middle_stage/Qwen_competion/qwen_compitition/console/src/mobile-local/tripSync.test.ts`
- `project_front/middle_stage/Qwen_competion/qwen_compitition/console/src/mobile-local/` 下对应三个镜像文件。

主要实现：

1. 新增 `stripAgentControlContent`，移除用户不可见的以下内容：
   - 完整或流式未闭合的 `lensgo-trip-update` 代码块；
   - `<lensgo-trip-update>` XML 控制块；
   - 能解析为有效行程提案的 `json` 代码块；
   - 回复末尾能解析为行程提案的裸 JSON；
   - HTML 内部注释。
2. 原始 QwenPaw 最终回复仍先交给 `extractAgentTripProposal` 解析，确保行程保存确认功能不受影响；用户可见消息使用过滤后的副本。
3. 流式 `onText` 阶段同步过滤，避免控制块在生成过程中短暂显示。
4. QwenPaw 最终入库和直连 API 回复入库均经过过滤。
5. 载入多会话历史和旧版单会话历史时自动清理已有助手消息，并将干净数据重新保存到本机；正常回复、用户消息和相册结果保留。
6. 如果模型只返回控制块而没有自然语言，界面显示简短的“行程方案已生成”提示，不产生空白气泡。
