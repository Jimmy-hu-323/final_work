# AI 交接记录使用说明

本目录只保存“某一次 AI 实际做了什么”的增量记录。项目长期架构、启动方法和服务器迁移方法分别以根目录的 `01_项目架构与文件说明.md`、`02_本地启动指南.md`、`03_服务器迁移部署指南.md` 为准。

## 开始工作

1. 先阅读根目录三份编号文档。
2. 按文件名时间顺序阅读本目录最近的记录。
3. 检查根仓库及三个后端子仓库的 `git status --short`，以当前源码和活动配置为最终事实源。

## 完成交接

每次有实际影响的任务都新增一份文件，推荐命名：

```text
YYYY-MM-DD_HHMM_简短主题.md
```

记录至少写明：

- 用户目标与工作范围；
- 修改文件和关键改动；
- 构建、测试、健康检查及结果；
- 当前运行服务、端口和临时状态；
- 未解决问题、风险和下一步；
- Git 提交或版本标签（如有）。

禁止覆盖旧记录。需要纠正时新增一份更正记录，并写清被更正的文件。

## 安全边界

不得记录 `.env`、`.dev.vars`、Token、密码、API Key、Cookie、用户照片、私密工作区原文或完整运行日志。只可写“已配置/未配置”、受保护文件路径和不含秘密的验证结论。
