# 对话完整行程宽度溢出修复

## 用户目标与范围

- 修复“对话”栏目在生成完整行程后，聊天内容突然超过手机屏幕宽度的问题。
- 仅修改对话页的消息显示样式，不改动其他栏目、聊天数据和后端业务逻辑。
- 构建并覆盖安装到 Type-C 连接的手机，使用出现问题的原完整行程进行回归验证。

## 原因

助手的完整行程包含 Markdown 大标题、较长的中文列表、预算表格文本、代码块和长行内容。对话消息使用 Flex 布局，但消息项和 Markdown 内容没有明确设置 `min-width: 0`，标题、列表、代码等子元素也缺少完整的断行及宽度限制。

因此浏览器会按这些内容的最小内容宽度计算消息气泡，长内容可突破消息容器并向屏幕右侧溢出，视觉上表现为整个对话突然变宽或放大。

## 修改文件与关键改动

仅修改了两份同步的对话样式文件：

- `project_backend/middle_stage/Qwen_competion/qwen_compitition/console/src/mobile-local/mobileLocal.module.less`
- `project_front/middle_stage/Qwen_competion/qwen_compitition/console/src/mobile-local/mobileLocal.module.less`

两份文件修改后 SHA-256 均为：

`21EEECC293F837A4978E949E0870FD42A62ADDE8FFC65C8FC8DD4E95242E0AB9`

具体修复：

1. 对话页面增加 `max-width: 100vw` 和 `box-sizing: border-box`，作为视口宽度的最终边界。
2. 消息滚动区和消息列表增加 `width: 100%`、`min-width: 0` 及横向溢出保护。
3. 用户和助手消息 Flex 项增加 `min-width: 0`，助手消息明确限制为可用宽度的 92%。
4. 消息气泡限制为扣除头像后的最大宽度，并启用 `overflow-wrap: anywhere` 与 `word-break: break-word`。
5. 将聊天 Markdown 的 H1-H6 标题调整为适合手机的字号和行高，长标题允许正常换行。
6. 列表、链接、图片和视频均限制在气泡宽度内。
7. 代码块和表格限制为气泡宽度；确实不能断行的内容只在自身内部横向滚动，不再撑宽整个页面。

所有新增规则都位于对话页专属类中，没有改变旅程、账单、相册、设置或 LensGo 首页的样式。
