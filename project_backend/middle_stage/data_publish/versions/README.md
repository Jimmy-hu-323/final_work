## 版本号规则

用 `主版本.次版本.修订号`：

- **主版本**：数据模型或 API 发生不兼容变更，接入方必须改代码。
- **次版本**：新增功能，向后兼容（v1.0.0 → v1.1.0 属于这类）。
- **修订号**：只修 bug 或改文档，不新增功能。

程序版本号的唯一来源是 `app/__init__.py` 的 `__version__`；
`/api/health` 的 `version` 字段和 HTTP `Server` 响应头都从那里读。

## 发新版本时要做的

1. 改 `app/__init__.py` 的 `__version__`；
2. 在本目录新建 `v<版本号>.md`，按下面的模板写；
3. 更新本文件的索引表；
4. 如果影响到接入方（新增/变更接口、数据结构），在版本文件里单独用
   「对接入方的影响」一节写清楚。

## 版本文件模板

```markdown
# vX.Y.Z

发布日期：YYYY-MM-DD
类型：新功能 / 修复 / 破坏性变更

## 一句话

## 新增功能

## 变更

## 修复

## 数据库变更
（有没有迁移？老库能不能直接用？）

## 对接入方的影响
（接口和数据结构变了吗？前端要不要改？）

## 验证情况
（哪些实测过、哪些没有——没验证的必须写明）

## 已知问题 / 未做的事

## 文件变动
```
