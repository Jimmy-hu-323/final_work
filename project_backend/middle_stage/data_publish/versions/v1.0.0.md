# v1.0.0

发布日期：2026-07-26
类型：首个版本

## 一句话

一个零依赖的本地 Web 服务，用来人工发布区 / 街道 / 景点的人流密度数据，
并通过 HTTP API 供主项目的地图页读取。

## 新增功能

### 数据模型

- 四张表：`cities`、`regions`、`batches`、`readings`。
- 三级区域层级 `district` / `street` / `poi`，用 `parent_id` 串联，
  对应地图的三档缩放。
- **库内坐标统一为 GCJ-02**，与主项目高德底图一致；录入 WGS-84 坐标时
  由 `geo.to_gcj02()` 自动转换。
- 拥挤度 `crowd_level` 0~4 决定颜色，`people_count` 保留原始人数；
  不填分级时按区域层级的阈值自动推导（区/街道/景点各一套阈值）。
- 「无数据」与「0 人」在 API 上明确区分（`reading` 为 `null`）。

### 发布机制

- 一次发布 = 一个批次（`batch_id`），整批写入或整批失败。
- 批次可整体撤销：删除该批读数，批次记录保留 `reverted` 状态留痕。
- `readings` 保留全部历史，不是只存最新，为以后的时间轴回放留出空间。

### 服务与接口

11 个接口：

```text
GET    /api/health                      服务状态与统计
GET    /api/meta                        层级、分级、阈值、当前权限
GET    /api/cities                      搜索城市
POST   /api/cities                      新增城市
GET    /api/cities/{id}                 城市详情
GET    /api/regions                     搜索区 / 街道 / 景点
POST   /api/regions                     新增区域
GET    /api/regions/{id}                区域详情
GET    /api/regions/{id}/history        历史读数
GET    /api/density/latest              地图页主接口
POST   /api/readings                    发布一批数据
GET    /api/batches                     发布历史
GET    /api/batches/{id}                批次明细
DELETE /api/batches/{id}                撤销批次
```

搜索支持中文名、英文名、别名和 region_id。搜「大三巴」会同时命中
圣安多尼堂区（别名）、大三巴街、大三巴牌坊。

### 访问控制

- 写接口：设了 `CROWD_WRITE_TOKEN` 就按 Bearer 校验；没设时**只接受本机请求**。
- 读接口：默认公开，方便地图前端直接调用；可用 `CROWD_READ_TOKEN` 收紧。

### 页面

五个标签页：发布数据、当前数据、发布历史、新增地点、API 说明。
原生 JS，无构建步骤，跟随系统深浅色。

「随机填充」按区域层级生成量级合理的随机人数，用于快速造演示数据。

### 内置数据

4 个城市、18 个区、12 条街道、40 个景点。澳门最完整：
8 个堂区/填海区、12 条重点街道、24 个景点；香港、广州、深圳各有若干区和
地标，用于验证多城市切换。

坐标以 WGS-84 书写，灌库时转 GCJ-02。

## 技术选型

不用 FastAPI，改用标准库 `http.server` + `sqlite3`——目标机器没装 FastAPI，
而一个内部工具不该要求先做依赖安装。业务逻辑集中在 `store.py`，以后换框架
只需重写 `api.py`。

## 修复

开发过程中发现并修掉的自身问题：

| 问题 | 影响 |
|---|---|
| 种子 SQL 占位符与参数数量不匹配（`area_m2` 既写了 NULL 又传了参数） | 首次建库直接报错 |
| `sqlite3` 的 `with conn` 只提交事务不关闭连接 | 长时间运行会泄漏文件句柄 |
| `latest_density` 的嵌套子查询写复杂了 | 改成按 `(observed_at, reading_id)` 排序取首条，逻辑更清晰 |
| 鉴权失败时未读完请求体就返回 | HTTP/1.1 keep-alive 下残留字节会污染下一个请求，改为出错即断开连接 |
| 日志里的 `⚠` 字符 | Windows cp936 控制台下 `print` 会抛 `UnicodeEncodeError` 把服务打挂，改为 ASCII 并给 stdout 加 `errors="replace"` |

## 数据库变更

首个版本，无迁移问题。首次启动自动建库并灌入内置数据。

## 对接入方的影响

首个版本，无既有接入方。

地图页要用的是 `GET /api/density/latest`，返回的 `center` 是 GCJ-02 的
`[lng, lat]`，`geometry` 恒为 `null`。

## 验证情况

**实测通过：**

- 浏览器实际操作五个标签页，无 console 错误。
- 完整发布流程：搜索 → 添加 → 随机填充 → 发布 → 当前数据显示。
- 拥挤度自动推导：区 21290 → 拥挤(3)、街道 2454 → 拥挤(3)、景点 1059 →
  非常拥挤(4)，与阈值一致。
- 跨城市搜索、层级筛选、分页。
- 批次撤销后 `latest` 归零。
- 负数人数、未知 region、非法 level 分别被 400 拒绝；不存在的区域 404。
- 写令牌：无令牌 401、错令牌 401、正确令牌 201、读接口仍 200。
- 静态资源路径穿越 `/../run.py` 被 403 拦截。
- WGS-84 → GCJ-02：大三巴 `[113.5406, 22.1976]` → `[113.5457, 22.1947]`，
  偏移约 500 米，符合预期。

## 已知问题 / 未做的事

1. **没有区域多边形**：`geometry` 恒为 `null`，只有中心点和影响半径。
   真实堂区边界需要从 OSM 提取并转 GCJ-02，街道级几乎没有现成面数据。
2. **没有层级自动聚合**：区的人数必须单独发布，不会由下属街道求和。
   混合规则（有独立值用独立值、没有就求和）尚未决定，表结构已支持。
3. **发布页没有地图**：只能从列表里挑区域。
4. **单机 SQLite**：够单人本地使用。
