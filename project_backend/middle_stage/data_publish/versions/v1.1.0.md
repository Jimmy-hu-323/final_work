# v1.1.0

发布日期：2026-07-26
类型：新功能（向后兼容）

## 一句话

接入高德地图：新增地图发布页，**高德上能搜到的任何地点都可以直接发布人数**，
不再限于内置的景点清单。

## 新增功能

### 地图发布页（新的默认标签页）

两种方式选定位置，都会在发布时自动把地点登记进库：

1. **搜索定位**：输入「大三巴牌坊」「广州塔」等 → 走高德 POI 搜索 →
   点结果地图飞过去 → 填人数发布。
2. **点击地图**：点任意位置 → 服务端做逆地理编码 → 自动带出地址，并列出
   附近 POI 供直接选择；也可以就用这个裸坐标点。

其他细节：

- 已有数据的地点以彩色圆点显示在地图上（颜色 = 拥挤度），点圆点可直接更新
  它的人数。这实际上就是主项目最终地图页效果的预览。
- 底图用高德栅格瓦片（GCJ-02，与主项目 `TravelPlanner` 同一个瓦片地址），
  不需要 Key。
- 深色主题下对瓦片做反相处理，避免整块刺眼白；标记不受影响。
- Leaflet 1.9.4 **本地化**到 `web/vendor/`，不走 CDN——本地工具不该因为断网
  就整页打不开。版本与主项目一致。

### 高德 Web 服务代理

新增 `app/amap.py`，封装三个高德接口：

```text
GET /api/amap/status              高德 Key 是否已配置
GET /api/amap/search?q=&city=     POI 关键字搜索
GET /api/amap/around?lng=&lat=    周边搜索
GET /api/amap/regeo?lng=&lat=     逆地理编码（坐标 → 地址）
```

**Key 只存在服务端，浏览器永远拿不到**：前端调本服务，本服务带 Key 去调高德。
与主项目 `travel_planner.py` 的做法一致。Key 放前端等于公开。

高德常见错误码翻译成了可读中文（`amap.INFOCODE_HINTS`），例如 10009 会提示
「Key 类型选错了，要 Web服务不要 JS API」——主项目 `START_LOCAL.md` 里踩过
这个坑。

### 高德地点登记

新增 `POST /api/regions/from-amap`，把一个高德 POI 或坐标点登记成可发布区域。
**幂等**：

- 有高德 POI id 的，按 `(external_source, external_id)` 唯一索引去重，
  重复添加返回已有记录（`created: false`）；
- 纯坐标点击的，按「同城 + 同名 + 30 米内」判定为同一地点。

高德返回的坐标本来就是 GCJ-02，这条路径不做任何转换，比手工录入少一层出错可能。

### 城市自动归属

这是「任何地址都能加」能成立的关键。给定高德返回的城市名 / adcode：

1. 命中内置别名（澳门特别行政区 → `macau`）→ 用内置城市；
2. adcode 已建过 → 复用；
3. 名称完全一致 → 复用；
4. 都不匹配 → 按 adcode 自动新建 `amap-<adcode>` 城市；
5. 高德没给城市名 → 就近归属到 80 公里内最近的已有城市，超出才报错要求指定。

所以搜「杭州西湖」会自动建出 `amap-330100` 城市，不用提前维护城市清单。

### 配置文件

新增 `.env` 支持（`config.load_env_file()`）与 `.env.example` 模板。已有的
环境变量优先，不会被文件覆盖。密钥只留在本机文件里，不需要出现在命令行、
文档或聊天记录中——`.env` 已被 `.gitignore` 排除。

## 变更

- **默认标签页改为「地图发布」**，原「发布数据」改名「批量发布」，功能不变。
- 版本号收敛为单一来源：`app/__init__.py` 的 `__version__`，`/api/health` 的
  `version` 字段和 HTTP `Server` 头都从那里读（之前 `1.0.0` / `1.0` /
  README 的 v1.1 三处不一致）。
- 城市下拉重建时保留用户当前选择，发布后自动刷新不会把选中城市弹回默认值。
- 中文名生成不出 slug 时，`region_id` 用高德 POI id 兜底
  （`macau-poi-b0ffhxxxxx`），比一串哈希好追溯。
- 服务启动日志会显示高德 Key 是否已配置（只显示前 4 位）。

## 修复

| 问题 | 说明 |
|---|---|
| 没有高德 Key 时点击地图发布必然失败 | 面板拿不到城市信息，`_resolve_city` 直接报错。改为两层兜底：前端传页面上「限定城市」的选择，后端按 80 公里内最近城市归属 |

这个 bug 是浏览器实测时发现的，不是推测。

## 数据库变更

**有迁移，老库可以直接用，不会丢数据。**

`db.migrate()` 用 `ALTER TABLE ADD COLUMN` 增量加列，启动时自动执行：

```text
regions.external_source   'amap' / 'manual' / 'seed'
regions.external_id       高德 POI id
regions.address           高德返回的详细地址
regions.adcode            高德行政区编码
regions.amap_type         高德 POI 分类
cities.adcode             行政区编码
```

外加一个部分唯一索引 `idx_regions_external ON (external_source, external_id)`
用于 POI 去重，和 `idx_cities_adcode`。

实测：在已有 70 个区域、3 条读数的库上迁移，数据一条没丢。

## 对接入方的影响

**接口向后兼容，前端不必改。**

- `/api/density/latest` 的返回结构没变，只是每个区域多了几个可选字段
  （`external_source`、`external_id`、`address`、`adcode`、`amap_type`）。
  忽略它们即可。
- `geometry` 仍然恒为 `null`，仍然用 `center` + `radius_m` 落点。
- 新增的接口都是可选的，不用也不影响原有流程。

## 验证情况

**实测通过：**

- 地图渲染 + 高德瓦片加载（HTTP 200）。
- 点击地图落点、面板开合、坐标显示（GCJ-02）。
- **完整发布链路**：点地图 → 填名称人数 → 自动登记地点 → 发布 →
  地图新增彩色圆点，颜色与人数对应（375 人景点 → 适中）。
- POI 幂等：同一个 `amap_id` 第二次提交返回 `created: false` 且是同一个
  `region_id`。
- 城市归属：`澳门特别行政区` 正确映射到内置 `macau`；`杭州市` 自动新建
  `amap-330100`。
- 无 Key 时 `/api/amap/search`、`/api/amap/regeo` 返回 502 + 可读中文原因，
  不是崩溃；页面顶部显示配置提示；地图底图和已有数据不受影响。
- 坐标参数非法返回 400。
- 数据库迁移在已有数据的库上执行，无数据丢失。
- 本地化的 Leaflet js/css 正常加载（HTTP 200）。
- 无 console 错误。

**没有验证的（重要）：**

- **高德的 POI 搜索和逆地理编码没有用真 Key 跑过**——写代码时本机没有 Key。
  这两条路径只验证了「没有 Key 时正确降级」。填入 Key 后请先点一次搜索；
  若报 `USERKEY_PLAT_NOMATCH` 就是 Key 类型选错了（要「Web服务」，
  不要「Web端(JS API)」）。
- 高德接口用的是 v3（`/v3/place/text`、`/v3/geocode/regeo`），兼容性最好，
  但没有在真 Key 上确认过响应字段。若字段有差异，改 `amap._normalize_poi()`
  一处即可。

## 已知问题 / 未做的事

沿用 v1.0.0 的三条（无多边形、无层级聚合、单机 SQLite），另加：

1. 地图上只能点坐标，不能点「区域面」——依赖多边形数据。
2. 高德接口没有做限流。高德有日调用量限制，如果把服务对外开放，代理层应加
   限流，避免额度被刷爆。
3. 搜索没有做输入联想（高德的 `inputtips` 接口），目前是敲完点「搜索」。
